## 一、测试环境与前提

| 前提 | 说明 |
|---|---|
| Node.js | v24.x（`.tool-versions` 钉 24.16.0；实测 v24.15.0 通过）|
| pnpm | 10.27.0（`packageManager` 钉定）|
| GaussDB 实例 | docker 运行中（`docker ps` 确认）；本地/自建容器（云上 sha256 见 README 边界）|
| 环境变量 | `GAUSSDB_URL=postgresql://appuser:<密码>@localhost:5432/n8n_test`（仅真库 journey 需要）|
| 环境变量 CI | **必须未设置**（`maxWorkers` 随 CI 变化会影响时限类 flaky 的计数）|
| dist | 全量套件前先 `pnpm build --continue`（10 个失败为 Windows 预存项，见 §五；`--continue` 保证其余 dist 产出）|

**安全约束**：认证失败**绝不重试**——GaussDB `failed_login_attempts=10`，连错 10 次锁号 1 天。

## 六、测试设计要点（维护者参考）

1. **whole-shape 断言**：ORM 用例一律 `toEqual` 整行 + 显式 `select`（仓库规则）
2. **方言快照**：渲染层测试直接断言生成的 SQL 字符串（如 ` ON DUPLICATE KEY UPDATE "name" = excluded."name"`），并带 `not.toContain('ON CONFLICT')` 防回退
3. **能力门测试**：`sql.lateral:false` 在 builder（运行时）与发射侧（descriptor-meta）双钉
4. **mock 钉**：ubtree/USTORE 归一化有免 GAUSSDB_URL 的 mock 级钉（control-adapter.test.ts:1075 起）
5. **私有 OID 的测试策略**：nvarchar2(3969)/clob(90)/blob(88)/raw(86) 在 PGlite 不存在——codec 单测纯函数化，wire 行为由真库 journey 覆盖
6. **行为级 RLS 验证**：第二账号（非 sysadmin）观察 policy 过滤；appuser 为 sysadmin 会被 RLS 豁免（探针教训，勿重蹈）
7. **flaky 协议**：清单外失败隔离复跑 2 次；时限/worker 崩溃（0xC0000409）类判 flaky，语义类判回归
