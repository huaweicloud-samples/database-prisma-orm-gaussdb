## 一、项目概述

为 Prisma ORM 8.0.0-rc.11 新增华为 **GaussDB 507（集中式 / Oracle 兼容模式 `sql_compatibility=A`）** 的独立 provider。不修改 postgres 现有能力，以平行包形态接入：

```
packages/3-targets/3-targets/gaussdb   @internal/target-gaussdb   DDL/codec/契约序列化
packages/3-targets/6-adapters/gaussdb  @internal/adapter-gaussdb  DML 渲染/能力声明
packages/3-targets/7-drivers/gaussdb   @internal/driver-gaussdb   node-pg wire 层
packages/3-extensions/gaussdb          @internal/gaussdb          gaussdb() 用户入口
packages/9-public/@prisma/orm-target-gaussdb                      发布壳（platform）
packages/9-public/@prisma/orm-gaussdb                             发布壳（facade）
```

共享代码（SQL family / framework）仅 11 个文件的**最小必要改动**（distinctOn 能力泛化 + authoring 工具链 4 处 gaussdb 并列），postgres 行为经 1607 测试复跑证实字节级不变。

## 二、关键决策记录

| 决策 | 结论 | 依据 |
|---|---|---|
| 接入方式 | 独立 provider，不蹭 postgres | 方言差异大（无 ON CONFLICT/LATERAL 等）；仓库 no-target-branches 规则 |
| codec 命名空间 | 独立 `gaussdb/*@1`（33 个） | 物理隔离彻底；provider 独立性体现在 targetId 而非复用 |
| 交付分期 | 运行时 → 迁移 → 内省，三期 | 参照 OceanBase 全流程交付标准 |
| upsert 语义 | 渲染层改写 `ON DUPLICATE KEY UPDATE`；DO NOTHING 非键列自赋值 | 真库探针 + Hibernate 同构先例 |
| **RLS** | **A+B 组合**：verify 对目录缺席 warn 化 + journey 第二账号行为验证 | 探针证实引擎生效但 policy 目录永久缺席（结构性不可观察）|
| **date 类型** | 不做原生映射，引导用 `timestamp` | wire OID 与 timestamp 撞车、ISO 输入被拒（`DD-MON-RR` 专有格式）|
| **varchar2** | 复用 varchar 通道 + 字节语义文档化 | 用户确认接受 Oracle 语义（UTF-8 字节计长）|
| ifNotExists | 渲染层剥离 + 存在性预检等价 | A 模式 42601；幂等语义保留 |
| lint:casts 棘轮 +63 | 新仓无 CI，暂不处置（用户决策） | 63 处为 fork 继承位点，零运行时影响 |
| Windows 工具链适配 | 不做（用户决策） | Linux 语义零变化但无本地验证手段，风险收益比不划算 |

## 三、交付全景（按期）

### 一期：运行时（连接 + CRUD + 事务 + upsert）

- 四层包 + `gaussdb<Contract>()` factory（连接串支持 `gaussdb://`/`postgres://`/`postgresql://`）
- 15 条真库 journeys 全绿：CRUD+returning、upsert 命中/未命中、事务 commit/rollback、distinctOn、LATERAL 能力门拒绝、空串→NULL 差异钉住
- 过程中修复 **八层控制面/渲染层方言缺陷**（bootstrap IF NOT EXISTS、to_regclass 缺失、introspection LATERAL、pg_policies/relrowsecurity 目录缺席、ledger 非空约束、ubtree 归一化、numeric 前导零）

### Sprint 1：方言深化

- serverless facade 连接串对称化
- jsonb 运算符 12 项真库定档矩阵（嵌套/`#>`/`@>`/`?` 族/构造函数；含 `#>` 紧贴词法坑与 4 个缺失函数替代）
- native-enum ADD VALUE 真库集成测试（事务内语义比 PG 12+ 更宽松，已实证）
- **Oracle 六类型映射**：number（复用 numeric 通道，39 位保真）/varchar2/nvarchar2/clob/blob/raw codec + authoring 条目 + round-trip journeys；node-pg Buffer 直绑实证；**numeric 前导零修复**（影响 A 模式全部 numeric 读取）

### S2-1：迁移（DDL，全形态）

- op 矩阵四轮真库探针 → **D1-D9 渲染缺陷全修**（TDD）：IF NOT EXISTS 剥离×3、RLS 目录预检、WITH CHECK/insert policy 显式能力报错、verify nativeType 别名对齐、hash 索引差异文档化、enum op 预检
- RLS A+B 决策闭环：第二账号行为验证（reader 0 行 / owner 2 行）
- 迁移 journeys 5/5：全形态契约 apply→verify 一次通过、增量 diff、ifNotExists 幂等、RLS 行为、能力错误显式化

### S2-2：发布壳

- 双壳登记：`@prisma/orm-target-gaussdb`（platform，44 键 exports）+ `@prisma/orm-gaussdb`（facade，140 键）——exports 离线推导经审查者独立复算，postgres round-trip 全等
- CLI `orm init` 四处登记：TARGET_ALIASES、目标选择器、包名映射、连通性探测（**不依赖版本号**——`server_version` 9.2.4 假象的规避设计）

### S3-1：内省

- 31 列真库逐列验证：25 直接通过、3 类按定档、4 缺口（nvarchar2/clob/blob/raw 推断）TDD 补齐
- round-trip 可执行性证明：infer 契约 → 空库 plan/apply → introspect verify strict 通过
- 新发现定档：A 模式 `date` 在 catalog 层为独立私有类型 `datea`
- 三个既有迁移层缺陷记录在案（见 §六遗留）

## 四、架构要点

- **三层职责**：target（方言 DDL/codec 契约）→ adapter（DML 渲染 + capabilities）→ driver（node-pg wire + SQLSTATE 错误归一化）；extension 组装为用户 factory
- **能力体系（capabilities）**：`gaussdb:{orderBy,limit,returning,jsonAgg}` + `sql:{enums,returning,defaultInInsert,scalarList,checkConstraint,distinctOn, lateral:false}`——LATERAL 由 builder 层自动拒绝（CAPABILITY_MISSING）
- **验证链路**：契约 → plan → apply（存在性预检幂等）→ introspect → verify（strict）；RLS 差异在目录缺席实例上 warn 化（A）+ 行为级验证（B）
- **发布形态**：`@prisma/orm-gaussdb`（facade，用户安装入口）+ `@prisma/orm-target-gaussdb`（platform）；CLI `orm init --target gaussdb`

## 五、方言适配要点（实测定档，完整版见测试文档与 README）

| 差异 | 处理 |
|---|---|
| 无 `ON CONFLICT` | 渲染层改写 `ON DUPLICATE KEY UPDATE`（`excluded.col` 可用）；DO NOTHING 非键列自赋值；更新冲突列显式报错 |
| 无 `LATERAL` / 聚合 `FILTER` | 能力门关闭 + 渲染层无生成路径 |
| 空字符串 → NULL | A 模式服务端行为，文档化（回读 null） |
| `WITH CHECK` / `FOR INSERT` policy | 内核级 42601 → 显式能力报错（含替代建议） |
| `ALTER TYPE ADD VALUE` | 支持（事务内可用，宽于 PG 12+） |
| hash 索引 / `USING` 裸运算表达式 | 不支持 / 与 stock PG 一致拒绝 |
| `number`/`varchar2`/`nvarchar2`/`clob`/`blob`/`raw` | Oracle 类型运行时全支持（详见 README 矩阵）；DDL 渲染已实现 |
| RLS | 引擎生效、目录缺席：verify warn + 行为验证；`no-default-deny` 分歧已记录 |

## 六、已知差异与边界（用户视角完整清单在扩展包 README）

1. RLS policy 目录缺席：introspection/verify 不可观察（warn），行为级验证可行
2. 云上生产实例默认 sha256 认证（华为私有）——node-pg 不支持，需 hba 降级或跳板；本地/自建容器无此问题
3. `to_json(blob/raw)` 输出 hex 文本进 JSON 投影（读侧安全，已探针）
4. jsonb 缺失函数：`jsonb_build_array`/`jsonb_agg`/`jsonb_object_agg`/`jsonb_path_query`（有替代写法）
5. `#>` 紧贴标识符的词法坑（Prisma 渲染带空格不受影响）
6. numeric 文本 |x|<1 丢前导零（已修复归一化，README 记录服务端行为）
7. 临时表禁 serial（0A000）
8. 内省产物不含 RLS 策略信息（目录缺席）

1. **TDD 强制**：全部实现先红后绿；破坏性验证补证（如 sed 回退渲染器验证方言测试判别力）
2. **双审查**：每任务独立规格合规审查（不信自述、实跑验证）+ 独立质量审查；审查发现的全部阻塞项闭环
3. **真库探针先行**：行为定档在写代码前完成（探针记录 `probe/verification-results.md` 十节）
4. **三线验收**：存量零回归（基线 57 文件清单对照）+ 新增全绿 + 真库全通
5. **决策门纪律**：语义级分歧（RLS/RLS 预设推翻/date）停下报决策，不自行假设
