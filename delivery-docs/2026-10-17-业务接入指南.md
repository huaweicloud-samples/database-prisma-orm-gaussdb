# GaussDB Provider 业务接入指南

- 面向读者：使用 Prisma ORM 8 + 华为 GaussDB（集中式 / Oracle 兼容模式）的业务开发团队
- 前提：GaussDB 507.0.0+（本地 docker 或自建实例；云上实例见 §六认证边界）

---

## 一、安装

```powershell
npm install @prisma/orm-gaussdb prisma
```

（发布壳已登记；npm 包随仓库推送后可用。当前阶段可用 workspace 路径或 git 依赖引用。）

## 二、连接与初始化

```ts
import { gaussdb } from '@prisma/orm-gaussdb';
import contractJson from './gaussdb/contract.json';
import type { Contract } from './gaussdb/contract';

const db = gaussdb<Contract>({
  contractJson,
  url: 'gaussdb://appuser:<密码>@localhost:5432/n8n_test',
});
```

- 连接串支持 `gaussdb://`（推荐）与 `postgres://`/`postgresql://`（别名），内部统一归一化
- 查询 DSL：`db.sql()` / `db.schema()` / `db.orm()`（与 postgres provider 完全同构）
- 事务：`await db.transaction(async tx => { ... })`

## 三、Schema 与迁移

### 3.1 新项目（从零建表）

1. 编写契约（PSL 或 TS builder，target = `gaussdb`）
2. plan/apply：控制面自动生成 DDL 并执行（全形态支持：标量全集、六 Oracle 类型、PK/UK/FK/CHECK、普通/唯一/复合索引、enum、RLS）
3. introspect verify 自动回读校验

幂等性：同一契约重复 apply 安全（存在性预检跳过已存在对象，等价 IF NOT EXISTS 语义）。

### 3.2 已有库（反向生成）

内省链路：`introspect({ driver })` → `inferPslContract` → 契约初稿 → 微调后即接入。31 类列型已真库验证（含六 Oracle 类型）。

边界：RLS 策略信息**不出现在内省产物**（GaussDB 目录缺席）；`date` 列（A 模式）推断为 `Unsupported("datea")`——请改用 `timestamp`。

### 3.3 手工建表的项目

跳过迁移，直接以 introspect 生成契约后按 3.1 使用运行时。

## 四、Oracle 兼容类型（A 模式专属）

| 声明 | 数据库类型 | JS 语义 | 注意 |
|---|---|---|---|
| `Number` | `number` | Decimal（39 位保真）| 与 numeric 同通道 |
| `VarChar2(n)` | `varchar2(n)` | string | ⚠️ **长度按 UTF-8 字节**（中文 3 字节/字），超长报 22001 |
| `NVarChar2(n)` | `nvarchar2(n)` | string | 字符语义，中文友好 |
| `Clob` | `clob` | string | 1MB+ 实测保真 |
| `Blob` | `blob` | Uint8Array/Buffer | 二进制直绑（含 0x00）|
| `Raw(n)` | `raw(n)` | Uint8Array ↔ hex | 仅 bare 拼写可内省 |
| ~~`Date`~~ | — | — | **不支持**：A 模式 date 与 timestamp 在 wire 层撞车，请使用 `Timestamp`（语义全覆盖）|

## 五、已知差异（迁移/查询时注意，完整版见扩展包 README）

1. **upsert**：`onConflict` 自动渲染为 `ON DUPLICATE KEY UPDATE`；`DO NOTHING` 用非键列自赋值模拟；更新冲突目标列会显式报错（GaussDB 拒绝更新主键/唯一键）
2. **无 LATERAL**：`lateralJoin()` 直接拒绝（CAPABILITY_MISSING）
3. **空字符串**：写入 text 列后回读为 `null`（A 模式 Oracle 语义）
4. **聚合**：无 `FILTER` 子句；`avg` 返回 16 位小数 numeric（数值等价）；`jsonb_build_array`/`jsonb_agg`/`jsonb_object_agg`/`jsonb_path_query` 不可用（有替代）
5. **RLS**：策略引擎生效但目录缺席——verify 对 RLS 差异 warn（不 fail）；策略行为请用非管理员账号验证（sysadmin 豁免 RLS）
6. **`WITH CHECK` / `FOR INSERT` policy**：不支持，plan 期显式报错（替代：条件并入 USING 或应用侧校验）
7. **hash 索引**：不支持（row store）
8. **UUID 默认值**：客户端生成；勿用 `@default(dbgenerated("gen_random_uuid()"))`
9. **版本判断**：GaussDB 的 `server_version` 上报 9.2.4、`version()` 无 PostgreSQL 字样——勿用版本号做能力判断
10. **jsonb**：等值/路径/包含/存在运算符可用（注意 `#>` 需与标识符留空格）；跨类型 `=` 不可用

## 六、认证与部署边界

| 场景 | 支持 | 说明 |
|---|---|---|
| 本地 docker / 自建实例 | ✅ | 开源 PG 驱动直连（node-pg）|
| 云上生产实例（默认 sha256） | ⚠️ | 华为私有认证，node-pg 不支持——需 hba 配置 md5、跳板代理，或等待后续版本 |
| 集中式多主机 | ✅ | JDBC 侧等价参数为 `targetServerType=master`；node-pg 侧用 `target_session_attrs` |
| 国密（SM 系列） | ❌ | 官方 Psycopg/驱动限定 |

运维建议：连接串带 `application_name` 便于服务端定位；注意 `session_timeout` 默认 1800s（池空闲时长应更短）；密码连错 10 次锁号 1 天。

## 七、常见问题

**Q：upsert 报 "GaussDB rejects ON DUPLICATE KEY UPDATE assignments to conflict-target columns"？**
更新负载里包含了冲突键列。移除该列的赋值（A 模式禁止更新主键/唯一键）。

**Q：报 "GaussDB cannot render DO NOTHING upsert: every column of this table is a key column"？**
插入列全部是键列且无可引用的非键列。在 INSERT 中带一个非键列，或改用 doUpdateSet。

**Q：写入空字符串后查出来是 null？**
A 兼容模式的 Oracle 行为（服务端转换），无法在客户端规避。需要区分空串请用可空列写 null 显式表达。

**Q：`lateralJoin` 报 CAPABILITY_MISSING？**
GaussDB 无 LATERAL 支持，这是预期行为。改写为子查询/JOIN。

## 八、支持矩阵速查

| 能力 | 状态 |
|---|---|
| CRUD / 事务 / 返回子句 | ✅ |
| upsert（ON DUPLICATE KEY UPDATE 语义） | ✅ |
| 迁移（全形态 DDL + 增量 + 幂等） | ✅ |
| 内省（schema 反向生成） | ✅（RLS 策略除外）|
| jsonb（等值/路径/包含） | ✅（嵌套路径与 4 个构造函数见 README）|
| 数组 / enum / RLS / 生成列 | ✅ |
| LATERAL / hash 索引 / WITH CHECK / FOR INSERT | ❌（显式报错）|
| 原生 date / 云上 sha256 / 国密 | ❌（见 §六/§四）|
